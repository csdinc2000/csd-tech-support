## 1) Tiny Prompt for Replit AI – Turn Existing App into a CRM

Use this inside your main backend file (or when Replit AI is open in the repo):

> You are updating this existing app into a mini-CRM for **Computer Systems Depot (CSD)**.
>
> **Goal:** Add simple CRM entities (Contacts, Leads, Jobs, Interactions) and REST APIs without breaking the current app.
>
> **Add data models:**
>
> * Contact: id, full_name, mobile_phone, email, contact_preference, address, tags, created_at, updated_at
> * Lead: id, contact_id, source, campaign, service_type, device_type, brand_model, operating_system, problem_description, call_id, status, priority, assigned_to, created_at, updated_at
> * Job: id, lead_id, job_number, job_type, status, scheduled_date_time, estimated_amount, final_amount, technician_notes, created_at, updated_at
> * Interaction: id, contact_id, lead_id, job_id, type, summary, details, performed_by, created_at
>
> **Add API endpoints (match this file’s current style/framework):**
>
> * Contacts:
>
>   * GET /api/contacts (list + search by name/phone/email)
>   * GET /api/contacts/:id
>   * POST /api/contacts
>   * PUT /api/contacts/:id
> * Leads:
>
>   * GET /api/leads (filters: status, source, date range, service_type, search)
>   * GET /api/leads/:id
>   * POST /api/leads
>   * PUT /api/leads/:id
> * Jobs:
>
>   * GET /api/jobs
>   * GET /api/jobs/:id
>   * POST /api/jobs
>   * PUT /api/jobs/:id
> * Interactions:
>
>   * GET /api/interactions (filter by contact_id/lead_id/job_id)
>   * POST /api/interactions
>
> **Intake form integration:**
>
> * Ensure there is a POST /api/intake endpoint that:
>
>   1. Finds or creates a Contact by phone/email
>   2. Creates a Lead using the request body
>   3. Saves source, campaign, call_id from URL/query params if present
>   4. Creates an Interaction of type "intake_form"
>   5. Returns the created lead + contact as JSON
>
> **Other requirements:**
>
> * Use the existing DB/ORM style already in this project.
> * Add basic server-side validation and error handling.
> * Keep code well-commented so a non-developer can understand what each part does.
> * Do not remove any existing routes; only extend the app.
>
> Please generate/modify the code in this file to implement these CRM features, step by step, explaining briefly what you changed at the bottom in comments.
