5. API DESIGN (CRM ENDPOINTS)

Create REST-style endpoints (or match the existing style) such as:

Contacts

GET /api/contacts – list, with search by name/phone/email.

GET /api/contacts/:id – details + related leads/jobs/interactions.

POST /api/contacts – create contact.

PUT /api/contacts/:id – update contact.

Leads

GET /api/leads – list with filters:

status, source, date range, service_type, search.

GET /api/leads/:id – lead + contact + interactions.

POST /api/leads – manual creation from admin UI.

PUT /api/leads/:id – update status, priority, assigned_to, etc.

Jobs / Work Orders

GET /api/jobs

GET /api/jobs/:id

POST /api/jobs (create from a lead)

PUT /api/jobs/:id

Interactions

GET /api/interactions (filter by contact_id/lead_id/job_id)

POST /api/interactions – add note, call log, etc.

Authentication can be simple (even just a basic “admin mode” guard for now), but keep code structured so real auth can be added later.
