## 1. COMPONENT STRATEGY & GLOBAL UI STANDARDS

### A. Semantic DOM & Layout Hydration
- **Zero Empty Containers:** Never render an empty placeholder or an unassigned root element (e.g., `<div></div>`). 
- **Skeleton States:** Every asynchronous component must possess an explicit, CSS-animated skeleton state to guarantee a Cumulative Layout Shift (CLS) score of near zero.
- **Error Boundaries:** Wrap all core interface entry points in global error boundaries. If a client-side asset route or real-time websocket thread drops, the interface must gracefully degrade to an actionable fallback screen rather than a blank or frozen shell.

### B. Core Security Header Compliance
Every server module, middleware layer, and reverse proxy routing matrix must strictly enforce the following security headers:
- `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`
- `X-Frame-Options: DENY`
- `X-Content-Type-Options: nosniff`
- `Content-Security-Policy`: Standardize to restrict script execution strictly to verified domains and backend proxies.

## 2. BACKEND API ARCHITECTURE & PROXY MANAGEMENT

### A. Total Secret Isolation
- **No Client-Side Credentials:** Absolutely no integration keys, provider tokens, database credentials, or sensitive platform parameters may ever cross the frontend barrier.
- **Mandatory Proxy Routing:** All external system interactions must be routed through an isolated server-side backend proxy. The frontend communicates exclusively with internal backend API routes via secure HTTPS.
- **Strict CORS Lockdowns:** Enforce hard origin verification via middleware. Drop any inbound request that does not originate from an explicitly whitelisted operational domain.

### B. Optimized Data Storage & Caching Layer
To eliminate unnecessary external API strain and manage request limits, all data streams must follow this precise structural matrix:

| Data Layer | Classification | Execution Strategy | Target TTL |
| :--- | :--- | :--- | :--- |
| **Static Assets** | Images, UI Frameworks, Core Logos | Hard Edge/CDN Caching | 30 Days |
| **Historical Data** | Immutable Audits, Historical Metrics, Closed Logs | Store in Local DB upon first fetch. Never call external APIs twice for static history. | Infinite (Immutable) |
| **Live Dynamic Data** | Active Metrics, Live System Status, Open Requests | Check Local Cache first. Only call external API if current timestamp exceeds TTL. | 15 Minutes |
